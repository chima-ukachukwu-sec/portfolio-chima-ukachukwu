How I approach AI security

Most AI security people came from machine learning. Most SOC analysts have never tested a model. I work from both sides, and the transfer runs in both directions.

Threat modeling, structured methodology and a security mindset move cleanly between traditional infrastructure and frontier AI systems. Knowing how detection fails in a SIEM tells you what an AI security control will miss. Knowing how a model fails tells you what is worth logging in the first place.

Background

I started in IT support and systems administration in 2014, running helpdesk, LAN/WAN and endpoint security before moving into security operations and then AI security. The infrastructure years are not background detail. Knowing how systems fail in production is what makes model failures legible.

On the offensive side I run adversarial testing against frontier large language models: jailbreak analysis, prompt injection assessment and misuse evaluation. I publish the sanitized methodology on GitHub rather than the working exploits. On the defensive side I worked a live enterprise SOC at Hobby Lobby Corporate IS, deploying MISP threat intelligence automation in Python and monitoring events with Splunk.

I hold an M.S. in Cybersecurity (GPA 3.7 / 4.0) from Oklahoma City University.
