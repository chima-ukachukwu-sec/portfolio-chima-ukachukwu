## Architecture decisions

1. **No supported attach command exists.** ProjectOS v1.1.0 ships `project-new`, which aborts
   on an existing target directory (`die("target already exists")` in
   `bin/project-new.v1.0.1.base`). Rather than hand-inventing a layout, the canonical generator
   was run into a scratch directory with the exact target flags
   (`--type web --risk moderate --premium-build yes --no-git`) and its output copied in. The
   artifacts are therefore canonical, not approximated.
2. **Risk `medium` maps to ProjectOS `moderate`.** ProjectOS's vocabulary is
   auto/low/moderate/high/critical. `moderate` is also the automatic default for type `web`.
3. **The generated `README.md` was not copied.** The repository has its own.
4. **Effort-to-phase mapping.** The refresh spans its own Phases 0 to 9. Those are recorded in
   `docs/ROADMAP.md`, which is ProjectOS's location for a multi-phase plan, and each becomes a
   numbered bounded phase spec in `docs/phases/` as it starts. No parallel tracking system was
   created. `PHASE-00-foundation.md` is the unused ProjectOS template and is retained because
   the structure check requires it.

## Security decisions

- **`.claude/skills/premium-build` is tracked. Everything else under `.claude/` is not.**
  The first draft of this phase left the whole directory ignored, which meant a fresh clone
  would fail `project-os-check` against the canonical v1.1.0 layout. Review corrected that.
  Because Git cannot re-include a path inside an excluded directory, `.gitignore`'s `.claude/`
  rule was replaced by a four-line ladder that narrows one level at a time:
  `.claude/*`, `!.claude/skills/`, `.claude/skills/*`, `!.claude/skills/premium-build`.
  The default at every level stays "ignored", so a new private file anywhere under `.claude/`,
  including inside `.claude/skills/`, is ignored without further edits. Exactly one path is
  tracked, and it is stored as a symlink blob (mode `120000`) whose content is the relative
  target, not a second copy of the skill tree.
- **Verified before committing** that `.claude/CANONICAL_FACTS.md`, `.claude/settings.local.json`
  and `.claude/launch.json` are still matched by `git check-ignore` (all three by the
  `.claude/*` rule), that five hypothetical future private paths are also ignored, and that
  `git ls-files .claude/` returns exactly one entry.
- **`AGENTS.md` carries rules, not the facts behind them.** It states no personal career fact.
  Work-authorization and clearance wording was removed on review and replaced by a rule that
  treats both as a protected class of claim: verify against `.claude/CANONICAL_FACTS.md`,
  reproduce the approved wording exactly, and if that file is unavailable, change nothing and
  ask. Scanned before commit: zero occurrences of the exam score, certification specifics,
  unsourced metrics, personal contact data, immigration status, clearance status, or
  compensation.
- **Public exposure of added files.** The repository is public and Pages-served with
  `.nojekyll`, so `AGENTS.md`, `docs/` and `.shared-skills/` are fetchable at the custom domain.
  All added content is public-safe by design. Flagged for the owner rather than mitigated,
  since excluding them is a site decision outside this phase.
- **Nothing outside this repository was mutated.** Verified: no file under
  `~/Developer/Projects/_ProjectOS` or `~/.ai-skills/premium-build` has a modification time
  from 2026-09-13, and the sibling ProductivityOS working tree is clean.
